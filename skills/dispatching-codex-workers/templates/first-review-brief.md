## SHA

Базовый: `[base_sha]`. Ревью: `[review_sha]` — коммит, которым автор сохранил работу перед этим
ревью (без push). Незакоммиченная работа на ревью не отдаётся: если рабочее дерево на момент
запуска отличается от `[review_sha]`, это ошибка запуска, а не повод ревьюить рабочее дерево —
сообщи об этом координатору через `ask`, не начинай ревью.

Смотри `git diff [base_sha]..[review_sha]` — это весь диапазон первого ревью.

## Scope

[Область этого ревью. Всё за её пределами — не анализировать здесь, только упомянуть отдельным

## Что проверить

1. Соответствие реализации каждому пункту требований — с конкретным местом в diff как
   доказательством, а не общей оценкой.
2. Попытка опровергнуть заявленные инварианты и граничные случаи, а не подтвердить ожидаемое.
3. Тесты — для каждого изменённого поведения: есть тест или явное обоснование, почему его нет.
   Для каждого найденного теста, привязанного к изменению:
   - тест привязан к конкретному требованию, не существует «на всякий случай»;
   - граница тестирования минимальная, но надёжная;
   - покрыты happy path, ожидаемый отказ и хотя бы одна краевая ситуация;
   - дефект — тест, повторяющий настройку mock без проверки поведения, или проверяющий только
     факт вызова;
   - литмус: убери ключевую строку логики — тест обязан упасть. Выполни литмус реально (или
     назови, почему нельзя) и укажи в отчёте результат по каждому тесту: требование → граница →
     сценарии (happy/failure/edge) → что показало удаление ключевой строки.

Диагностируй, не переписывай: находка называет конкретный пробел и критерий закрытия, доработку
делает автор.

## Отчёт

Первая строка: `DONE` при отсутствии находок, иначе `DONE_WITH_CONCERNS` с полным списком.
Далее: находки с ID, местом в diff, критерием закрытия; отдельно — темы вне scope без
развёрнутого анализа. Заверши `worker_done` с подходящим `--outcome succeeded|failed`.
